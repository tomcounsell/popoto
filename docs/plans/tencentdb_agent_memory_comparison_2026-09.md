## (a) One-paragraph summaries

**TencentDB Agent Memory** is a TypeScript, service-shaped "team-level memory hub" for coding agents. Conversations are captured into a four-layer store (L0 raw conversation → L1 atomic facts → L2 scenario blocks → L3 persona/profile), refined by an async LLM pipeline, and retrieved layered: L2/L3 for a quick bootstrap, BM25 + vector + RRF falling back to L1/L0 for specifics (`TDB:README.md` "Technical Implementation"). Since v2 it manages four asset classes — Chat Memory, Skills, Wiki, CodeGraph — with private/team/restricted/agent visibility and ACLs, administered through a React "Memory Panel" and delivered to agents either by a transparent LLM proxy (`MemoryProxy`, which forwards OpenAI `/v1/chat/completions` and Anthropic `/v1/messages` verbatim and injects/captures around them) or by per-harness plugins (OpenClaw, Hermes, Pi) (`TDB:MemoryProxy/README.md`, `TDB:MemoryCore/README.md`). Default storage is SQLite + sqlite-vec with Tencent Cloud Vector Database (TCVDB) as the hosted backend and an experimental MongoDB mode; an LLM API key is required (`TDB-main:README.md`, `TDB:README.docker.md`, commit `#1292`). MIT licensed, 26,169 stars, 16 releases since 2026-04 (`TDB-API:` root, `/releases`).

**Popoto Agent Memory** is a Python library, not a service: a Redis/Valkey ORM with Django-like model syntax on which 18 memory field types and mixins are composed (`DecayingSortedField`, `CyclicDecayField`, `ConfidenceField`, `CoOccurrenceField`, `BM25Field`, `ValidityField`/`SupersessionProtocol`, `AppendOnlyMixin`, `NeverRecordMixin`, `TagField`, …) plus policy layers on top — `ContextAssembler`, hybrid RRF retrieval, `SubconsciousMemory`, `MemoryLifecycle`, `ProvenanceJournal`, `PolicyCache`, telemetry, and a metacognitive layer (`docs/features/agent-memory.md`). It runs in-process against a Redis or Valkey the operator already has, uses no Redis modules (Lua, sorted sets, streams, SETBIT bloom filters only), needs no API key (`pip install popoto` = 3 packages, 9.0 MB), and defaults to raw-turn ingestion because LLM extraction measured worse on its own judged harness (`README.md`, `docs/features/llm-memory-extraction.md`). Harness integration is hook-first (Claude Code, Codex, Hermes, OpenClaw pre/post-model hooks) with MCP reserved for discretionary search/save/correct (`docs/features/harness-integration.md`). Every published number is backed by a committed JSON artifact, including negative results (`docs/benchmarks.md`). MIT, 1.9.0 on PyPI, 9 GitHub stars, 5 contributors (`gh api repos/tomcounsell/popoto`).

## (c) Key contrasts

**Service vs. library.** TencentDB is four deployable components (MemoryCore gateway, MemoryProxy, MemoryKnowledge, MemoryPanel) that an organization stands up; agents point at it over HTTP. Popoto is code that runs inside the agent process against a Redis the operator already runs. The former buys a control plane, ACLs, and a UI; the latter buys zero infrastructure and no new network hop. TencentDB's proxy in particular sits *on the LLM request path* and forwards `/v1/messages` verbatim with injection — a powerful zero-code integration that also means every model call transits their proxy.

**Who does the thinking.** TencentDB's memory quality depends on an LLM at every consolidation step (L1 extraction, L2 induction, L3 profiling, skill extraction, Wiki extraction), so it requires `TDAI_LLM_API_KEY` and its outputs are as good as the model and prompts. Popoto measured LLM extraction against raw ingestion on its own judged harness and shipped raw as the default; consolidation is mechanical (access counts, confidence thresholds, decay). Popoto's design bet is that retrieval ranking plus outcome feedback beats summarization; TencentDB's bet is that distilled layers reduce tokens and improve task success. TencentDB's headline token-reduction and SWE-bench claims, if real, are evidence for their bet — but nothing in the tree lets a reader check them.

**Time and truth.** Popoto has an explicit theory of a memory's lifecycle: decay, confidence moving with evidence, bitemporal validity, supersession chains, append-only provenance with `as_of` replay, restorable tombstones. TencentDB has versioned atoms and manual delete/clear, plus roadmap items to edit L1–L3 in the panel. Neither system has a documented equivalent of the other's strength: TencentDB has no decay/confidence; Popoto has no review-and-publish workflow.

**Scope of "memory".** TencentDB's four assets make Skills, Wiki, and CodeGraph peers of chat memory, with a Git indexer and doc ingestion pipeline. Popoto's memory is records with scores; documents and code are out of scope. Popoto's `PolicyCache` (crystallized state-action-outcome patterns) is the nearest analogue of Skills but is far less developed as a product surface.

**Sharing model.** TencentDB enforces `team + agent + user` isolation and layers ACL/visibility/binding on top — governance is a feature. Popoto offers scoping primitives (`KeyField` partitions, `TagField`) on one central Redis and leaves policy to the application; the north star is "fully subconscious" operation, not administration.

**Privacy at capture.** Popoto's never-record firewall is the one privacy mechanism that is deterministic and on by default; TencentDB's privacy story is about *who can read* stored memory, and no capture-time secret filter was found (UNVERIFIED that none exists in `src/`).

**Evidence culture.** Popoto publishes granularity caveats, corrected-scoring history, and negative results next to headline numbers, and anchors against MEMTIER. TencentDB publishes larger, more marketable numbers (PersonaMem +59%, SWE-bench, token cuts) with no visible artifacts. In a head-to-head pitch the TencentDB numbers will win attention; in a technical audit Popoto's will survive.

**Adoption.** 26k stars, Tencent's brand, seven proxy-adapted agents and three plugins versus 9 stars and four hook-integrated harnesses. TencentDB's default branch being `feat/server_team` and a same-day v1.0.2 + v2.0.2-beta.1 release pair suggest a fast-moving, somewhat unsettled v2.

## (d) SWOT for Popoto relative to TencentDB

### Strengths
- **Zero-dependency, in-process operation.** 3 packages / 9.0 MB, no API key, no service, no proxy on the LLM path (`README.md`), versus a Node 22 stack, ~920 MB image, mandatory `TDAI_LLM_API_KEY`, and a request proxy (`TDB:README.docker.md`, `TDB:MemoryProxy/README.md`).
- **Richer memory dynamics.** Decay, cyclic pressure, capped-Bayesian confidence tied to `acted/dismissed/contradicted` outcomes, bitemporal validity and supersession, restorable tombstones (`docs/features/observation-protocol.md`, `validity-and-supersession.md`, `docs/recipes.md`); TencentDB's v3 API documents only manual delete/update and no decay (`TDB:MemoryCore/v3-api-memorycore-doc.md`).
- **Deterministic privacy at capture.** Never-record firewall on by default with enumerated guarantees and holes (`docs/features/never-record-firewall.md`); no equivalent located in TencentDB.
- **Auditable benchmarks.** Committed JSON artifacts, pinned judge hashes, negative results, MEMTIER anchor (`docs/benchmarks.md`); TencentDB's numbers have no visible harness or artifacts.
- **Valkey-safe by construction.** No Redis modules, Lua + native structures only (`docs/features/agent-memory.md`), so it runs on any Redis-compatible server the operator already has.

### Weaknesses
- **No team governance.** No ACL, visibility levels, review/share workflow, or admin UI; `TagField` and `KeyField` scoping are primitives, not policy (`docs/fields.md` §TagField, `docs/multi-tenancy.md`). TencentDB ships private/team/restricted/agent visibility, ACL grant/revoke, and a control panel (`TDB:README.md`).
- **Narrow definition of memory.** Records only; no document ingestion, Wiki, code graph, or Skills asset class (`docs/features/agent-memory.md`). TencentDB's four assets and `/v3/tools/*` discovery cover a much larger surface (`TDB:MemoryKnowledge/README.md`).
- **Python-only, hook-only integration.** Four harnesses via hooks/MCP, two of them verified only against docs or a schema (`docs/features/harness-integration.md`); TencentDB's proxy needs no plugin at all and adapts seven agents plus OpenCode (`TDB:agents/README.md`).
- **No end-task or token-savings evidence.** Popoto reports retrieval recall and latency; nothing like SWE-bench or token reduction (`docs/benchmarks.md`), which is what TencentDB leads with (`TDB-main:README.md`).
- **Visibility and community.** 9 stars, 5 contributors versus 26,169 stars, 2,451 forks (`gh api`, `TDB-API:` root).

### Opportunities
- **Be the memory substrate under a hub.** TencentDB's service mode already uses Redis for state (`TDB:README.docker.md`); Popoto's primitives could be positioned as the durable, decaying, Valkey-safe store beneath a governance layer that someone else builds, or beneath a thin Popoto-native "hub" recipe.
- **Ship a proxy adapter.** A transparent `/v1/messages` + `/v1/chat/completions` proxy that calls `MemoryService.assemble()`/capture would give zero-code coverage of every OpenAI/Anthropic-protocol agent, matching TencentDB's widest integration path (`TDB:MemoryProxy/README.md`) while keeping the hook path as the reference.
- **Publish task-level and token benchmarks with artifacts.** TencentDB's PersonaMem and token-cut claims are unaudited; a Popoto run on PersonaMem with committed JSON and a token-consumed column would be the first checkable number in that comparison (`docs/benchmarks.md` already has the judged-answer harness).
- **Governance as primitives.** TencentDB's visibility table (`private/team/restricted/agent`) maps naturally onto a `TagField`-plus-owner pattern; a `VisibilityMixin` with a read-filter hook would close the biggest feature gap without becoming a service.
- **Harvest their open issues.** 802 open issues on a 5-month-old repo (`TDB-API:` root) are a public list of what adopters of a service-shaped memory hub struggle with; several (bash 3.2 quoting, proxy identity on cache miss — `TDB-API:commits`) are deployment pain a library avoids.

### Threats
- **Default-by-distribution.** Tencent's brand, 26k stars, and a proxy that requires "no plugin, hook, or MCP server" (`TDB:README.md`) can make TencentDB the default memory for the Claude Code/Codex/OpenClaw/Hermes users Popoto targets (`docs/features/harness-integration.md`).
- **Marketable numbers.** "+59% PersonaMem", "−61% tokens", "SWE-bench +9.93%" (`TDB:README.md`, `TDB-main:README.md`) are end-task metrics; Popoto's recall/MRR, however honest, answer a question buyers ask less often.
- **Asset-class expansion.** Skills/Wiki/CodeGraph turn "memory" into a knowledge platform; if that framing wins, a records-only library reads as incomplete regardless of ranking quality.
- **Ecosystem lock.** TencentDB's hosted backend is TCVDB with migration tools from SQLite (`TDB-main:CHANGELOG.md` 0.2.0); a team that adopts it accrues assets in a Tencent-shaped schema and API (`/v3/*`), raising switching cost before Popoto gets a look.
- **Fast iteration on an unsettled v2.** Same-day v1.0.2 and v2.0.2-beta.1 releases and a feature-branch default (`TDB-API:releases`, root) indicate they are shipping weekly; the governance gap Popoto could close is one they are actively widening.

## (e) What we could borrow

1. **Visibility levels and agent loadout** — `private / team / restricted / agent` semantics and "fixed binding + ACL, then retrieve" ordering (`TDB:README.md`). Implementable as a mixin over `TagField` plus an owner field and a read filter in `ContextAssembler`.
2. **Transparent proxy integration** — forwarding OpenAI/Anthropic protocol verbatim with injection and write-back (`TDB:MemoryProxy/README.md`) as an alternative to hooks for harnesses without a stable hook surface (Hermes is docs-verified only today).
3. **Layered retrieval budget** — bootstrap from a compact summary layer first, fall back to atoms/raw only when the query needs specifics, with item/char/timeout caps (`TDB:README.md` "Technical Implementation"). Popoto's `MemoryLifecycle` episodic/semantic tiers could feed a two-stage assembly.
4. **Symbolic short-term memory / context offload** — replace verbose tool output in context with `node_id`-referenced summaries and a drill-down path (`TDB-main:README.md`), which is complementary to Popoto's prompt-cache-efficiency work.
5. **Cold-start import** — importing existing sessions, docs, and repos so a new agent starts with the team's "save file" (`TDB:README.md` "Cold Start"); Popoto's `popoto-transfer` export/import is the natural home.
6. **Editable memories with version auto-increment** (`/v3/atomic/update`, `TDB:MemoryCore/v3-api-memorycore-doc.md`) — Popoto's `SupersessionProtocol` already gives the semantics; a `memory_correct` MCP tool that supersedes rather than edits would expose it to harness users.
7. **PersonaMem as a benchmark** — the one dataset both projects could report; adding it to `run_external.py` with committed artifacts turns their headline into a checkable comparison.
